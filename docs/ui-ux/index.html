Style guide v2

Calm, fast, thumb-first.

Exvia is a mobile PWA for riders: clans, rides, maps and a personal garage. Its visual language is the Minimals design system (minimals.cc): Public Sans and Barlow type, a green primary, soft layered shadows and 16px cards. On top of it sit the mobile rules and the UX laws from docs/base. Design for a 360px wide phone first, then scale up.

Principles

Look and feel (Minimals)

  • Minimals first. Color, type, radius, shadow and component styling follow the Minimals theme. Exvia only adds the mobile structure.
  • Soft depth. Cards float on a layered shadow with 16px corners, dashed hairlines divide rows, and bars and sheets are blurred paper.
  • Neutral ink, one green. Default buttons are ink. Primary green marks the one key action, the current tab and selected controls. Status colors appear as soft tints.
  • Data voice. Distances, times and counts are set in Barlow bold with tabular figures, so numbers read like instruments.
  • Light and dark. Every color token is a light-dark() pair that follows the OS setting.

Interaction rules (UX laws)

  • Thumb zone (Fitts). Navigation, primary buttons and the sheet live in the bottom half. The main action is 48px tall and at least 120px wide.
  • 44px hit area (Fitts). Everything tappable has a 44px target. Compact controls (small buttons, chips, segments) look 36px or less and extend their hit area.
  • Under 400ms (Doherty). Transitions take 150 to 300ms. Show a skeleton shaped like the content, update optimistically, never leave a blank screen.
  • Group by distance (Proximity, Chunking). 8px inside a group, 16px between siblings, 32px between groups. Split long forms into fieldsets of 3 to 4 fields.
  • Few choices (Hick, Miller). 3 to 5 tab bar destinations, 2 to 4 segments, at most 5 chips and 7 menu options. Group or fold the rest.
  • Reveal progressively (Cognitive Load, Tesler). Start from smart defaults, fold advanced options in a disclosure, and use sheets for secondary flows instead of dialogs.
  • Every state has a way forward (Peak-End, Goal-Gradient, Zeigarnik). Empty, success and error views carry an icon, a message and one action. Multi-step flows say "Step 2 of 4". Unfinished work shows what is left.

Layout and PWA

Every screen is a single column inside .screen (max 30rem). On larger viewports the column stays centered; do not stretch content.

  • App shell. Blurred top bar (56px), scrolling content, blurred tab bar with 3 to 5 destinations.
  • Safe areas. Use --safe-top and --safe-bottom on bars so content clears the notch and home indicator. Requires viewport-fit=cover.
  • Breakpoints. Mobile base, 48rem tablet, 72rem desktop. Use min-width only.
  • Desktop navigation (Jakob). From 72rem the tab bar must move to a left rail or the top bar, never stay at the bottom. No desktop shell exists yet.
  • Standalone mode. The manifest uses display: standalone and a theme_color matching --color-bg, with a theme-color meta per color scheme.
  • Overscroll. Body disables vertical overscroll bounce to avoid accidental pull-to-refresh; opt in per list.
  • Offline. Show skeletons while loading and an alert when offline. Never block the screen on the network.
  • Inputs. Set type, inputmode and autocomplete so the right keyboard appears, and accept any reasonable format.
